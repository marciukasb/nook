# Nook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Android app (Kotlin, Compose) with three tabs — Groceries, Shopping, Tasks — on top of the owner's Todoist projects, offline-safe via Todoist's Sync endpoint, with learned categories and self-updates from GitHub.

**Architecture:** Single `app` module. Pure-Kotlin logic (`core/`) has no Android imports and is tested on the JVM. A Room database is the only thing the UI reads; a `SyncEngine` applies optimistic local changes, queues Todoist sync commands (stable uuids) and reconciles with `POST /api/v1/sync`. Transport is an interface so tests use an in-process `FakeTodoist`.

**Tech Stack:** Kotlin 2.x, Jetpack Compose + Material 3, Room, WorkManager, OkHttp, kotlinx.serialization, kotlinx.coroutines; tests: JUnit4, Robolectric (Compose UI tests run on the JVM), kotlinx-coroutines-test, work-testing.

**Spec:** `docs/superpowers/specs/2026-11-21-nook-design.md`

## Global Constraints

- Package `lt.nook.app`; app label `Nook`; UI strings in English.
- compileSdk/targetSdk 36 (installed: `platforms/android-36.1`, build-tools 36/37), minSdk 26.
- Build JDK: Android Studio's bundled one — `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`; `ANDROID_HOME=$HOME/Library/Android/sdk`. Every Gradle command below assumes both.
- Todoist API base `https://api.todoist.com/api/v1`; only `POST /sync` and `GET /tasks/completed/by_completion_date`. Sync commands used: `item_add`, `item_close`, `item_uncomplete`, `item_move`, `section_add` — nothing else.
- No real Todoist account or token anywhere in code, tests, fixtures, logs or git. The token lives only in the on-device encrypted store and is never logged (OkHttp logging, if any, must redact `Authorization`).
- Release signing key at `~/.nook/release.jks`, credentials in `~/.nook/keystore.properties` — both outside the repo; `.gitignore` also blocks `*.jks`, `*.keystore`, `keystore.properties`, `local.properties`.
- Default project names exactly `Groceries`, `Shopping`, `Shared tasks`.
- Test command for every task: `./gradlew testDebugUnitTest` (Expected: `BUILD SUCCESSFUL`).

## Review Focus

1. A remembered section was renamed/deleted in Todoist → suggestion still shows the item but adding asks for a category instead of failing or recreating the old section. (Task 6 test `memory_sectionGone_asksAgain`.)
2. App killed between a tap and the flush → the queued command is in Room and is sent on next start, exactly once. (Task 5 test `queue_survivesRestart_sentOnce`.)
3. Phone B ticks an item that phone A has a queued move for → A's command fails per-command, local state reverts, a message names the item, the queue continues. (Task 5 test `perCommandError_revertsAndContinues`.)
4. Token revoked (401/403) with commands queued → queue kept, status shows "Sign in again", nothing dropped; signing out clears everything. (Task 5 `authError_keepsQueue`, Task 7 `signOut_clearsDatabase`.)
5. Todoist answers 429/5xx → exponential backoff (max 5 min), status "Not synced yet (N changes)", no tight loop. (Task 5 test `rateLimited_backsOff`.)

### Task 5: Local database and SyncEngine

**Files:**
- Create: `app/src/main/java/lt/nook/app/data/Db.kt` (entities, DAOs, `NookDb`), `sync/SyncEngine.kt`, `sync/SyncState.kt`
- Test: `app/src/test/java/lt/nook/app/sync/SyncEngineTest.kt` (Robolectric, in-memory Room)

**Interfaces:**
- Consumes: Task 4 `Transport`, `Command` builders, `SyncResponse`, `SyncError`; Task 3 `ItemV/SectionV`.
- Produces:
  - Entities `ItemE` (id, projectId, sectionId?, parentId?, content, order, responsibleUid?, dueDate?, dueString?, recurring, hidden: Boolean), `SectionE`, `ProjectE`, `PersonE(id, name, projectIds)`, `PendingE(uuid PK, seq autoincrement, json, itemId?, undoJson?)`, `MetaE(key, value)` (sync_token, user_id, last_error).
  - `enum class Kind { GROCERIES, SHOPPING, TASKS }`.
  - `class SyncEngine(db: NookDb, transport: Transport, token: () -> String?, projectNames: () -> Map<Kind,String>, clock: () -> Long)` with:
    - `val state: StateFlow<SyncState>` — `SyncState(status: Status, pending: Int, message: String?)`, `Status { Synced, Syncing, Offline, SignInAgain, ProjectsMissing(names) }`.
    - `fun items(kind): Flow<List<ItemV>>`, `fun sections(kind): Flow<List<SectionV>>`, `fun people(): Flow<List<PersonE>>`, `fun projectId(kind): String?`.
    - `suspend fun add(kind, content, sectionId: String?, assignee: String?): String` (returns temp id; sectionId may itself be a temp id from `newSection`), `suspend fun tick(itemId): TickResult` (`Hidden(undoToken)` or `Advanced(nextDate)` for recurring, which stays visible), `suspend fun undo(undoToken)`, `suspend fun move(itemId, sectionId: String?)`, `suspend fun newSection(kind, name): String`, `suspend fun flush()`.
  - Rules: every action writes local state + `PendingE` in one Room transaction, then calls `flush()`. `flush()` sends all pending in `seq` order with the stored sync_token; on response applies `temp_id_mapping` to items/sections/pending, deletes acknowledged `PendingE`, reverts + sets `message` for `Failed` ones, then merges server state except items referenced by still-pending commands. `full_sync` replaces the three projects' data. Ticking a parent hides open descendants too and its undo reopens them (`item_uncomplete` per id). Recurring tick: `item_close` + keep visible, `Advanced` result, no undo token.
  - Errors: `Auth` → `SignInAgain`, queue kept; `RateLimited/Server/Offline` → `Offline`, next allowed attempt after backoff 5 s ×2 up to 300 s (Retry-After respected); success resets.
